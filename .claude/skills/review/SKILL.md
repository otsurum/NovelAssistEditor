# レビュー / テスト（Phase 4）

**対象は `git diff` の差分のみ。** リポジトリ全体を読み直さない。
各項目を **1 行**（OK / NG ＋ 理由 1 文）で記録する。長文の講評・点数は書かない。

- [ ] **要件** — 計画書の受け入れ条件を、紐づけた確認方法で確かめたか
- [ ] **スコープ** — diff に計画外のファイル・変更が含まれていないか
- [ ] **不要なコード** — 未使用のヘルパー、過剰な抽象化、コメントアウトの残骸
- [ ] **テスト** — 変更範囲のテスト ＋ 最後にフルテスト 1 回
- [ ] **禁止事項** — 破壊的コマンド、履歴を壊す git 操作、秘密情報

**5 項目すべて OK のときだけ受け入れる。** 1 つでも NG なら修正ループへ。

**修正ループ:** 軽微な指摘はその場で直す。**チケットを発行するのは人間の判断が必要な指摘だけ。**
修正後は再度このチェックリストを回す。**上限 2 回**、超えたら人間に通知（解決できていないこと／詰まっている箇所／試したこと）。

レビュー体制は現時点ではセルフレビュー（AI と担当者）とする。

**完了条件:** 全項目 OK、修正チケットが残っていない。
